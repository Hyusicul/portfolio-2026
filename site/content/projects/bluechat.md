## 프로젝트 개요

**Blue Chat**은 사용자 간 실시간 메시지 교환을 지원하는 **Android 채팅 애플리케이션 개인 프로젝트**입니다. 카카오톡·텔레그램과 같은 메신저를 참고하여 1:1 대화, 오픈 채팅방, 비밀 채팅방, 친구 관리, 이미지 공유 등을 구현했습니다.

- **개발 형태:** 모바일프로그래밍 개인 프로젝트
- **주요 기술:** Kotlin, Android Studio, Firebase Authentication, Cloud Firestore, Cloudinary
- **담당 역할:** 앱 구조·화면·데이터 연결·채팅 기능의 설계 및 구현

## 구현한 주요 기능

1. **계정 및 사용자 관리:** Firebase Authentication의 이메일/비밀번호 로그인을 연동하고 프로필·닉네임·친구 정보를 Firestore에서 관리합니다.
2. **다양한 채팅방:** 1:1 대화, 여러 사용자가 참여하는 오픈 채팅방, 초대 기반 비밀 채팅방을 구성했습니다.
3. **실시간 채팅:** Firestore의 실시간 동기화를 이용해 메시지 목록을 갱신하고, 기기 시계 차이로 인한 순서 혼란을 줄이기 위해 서버 타임스탬프를 사용했습니다.
4. **이미지 전송:** 용량이 큰 이미지 파일은 Cloudinary에 업로드하고, Firestore에는 이미지 자체가 아닌 **이미지 URL과 메시지 정보**를 저장하도록 구성했습니다.
5. **사용 편의 기능:** 닉네임으로 친구 추가, 차단 및 해제, 채팅방 즐겨찾기, 메시지 검색, 안 읽은 메시지 수 표시, 한국어·영어 전환 등을 구현했습니다.

## 설계 및 개발 과정

- `FirebaseRefs.kt`에 사용자·닉네임·친구 요청·채팅방 등 Firestore 컬렉션 접근을 모아 관리했습니다.
- `MainActivity.kt`에서 화면 전환을 제어하고, 채팅 목록은 `ChatRoomAdapter.kt`와 `RecyclerView`로 표현했습니다.
- `CloudinaryManager.kt`로 이미지 업로드를 분리하고 채팅 화면에서 업로드된 이미지의 URL을 메시지와 연결했습니다.

## 기술적 문제와 해결 경험

**기기마다 메시지 시간이 다르게 표시되는 문제**가 있었습니다. 초기에는 기기 시간을 기준으로 메시지 순서를 기록했지만, 기기 간 시간이 달라 순서가 뒤바뀔 수 있었습니다. 이를 **서버 타임스탬프 중심으로 변경**하여 시간 기준의 일관성을 개선했습니다.

또한 이미지 파일을 Firestore에 직접 보관하지 않고 외부 이미지 저장소에 업로드한 뒤 URL만 저장함으로써 역할을 분리했습니다.

## 한계 및 개선 방향

- **푸시 알림 미구현:** 앱을 열지 않았을 때 새 메시지 알림을 받기 어렵습니다.
- **비밀 채팅의 보안:** 비밀 채팅방은 참여자 제한 기능이며, **종단 간 암호화(E2EE)를 구현한 것은 아닙니다.** 실제 사용 서비스라면 접근 제어와 보안 강화가 필요합니다.
- **가입 및 계정 복구:** 테스트용 이메일 가입이 가능한 구조의 한계가 있어, 실제 서비스에는 이메일 검증과 복구 체계가 필요합니다.
- **확장성:** 무료 서비스 용량·비용, 대용량 파일/영상/음성 전송 및 일부 화면의 갱신 동작을 개선해야 합니다.

## 배운 점

실제 동작하는 채팅 앱을 처음부터 구성하면서 **클라이언트와 서버 역할의 구분, 실시간 데이터 동기화, 파일 저장소와 데이터베이스의 분리, 예외 처리의 중요성**을 배웠습니다.
